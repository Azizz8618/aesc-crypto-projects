# Работа с эмуляторами УЭВС: пакетный dispak и полносистемный simh

Документ собирает в одном месте практическую информацию о работе с двумя
эмуляторами учебно-экспериментальной среды БЭСМ-6: пакетным (задачным)
`dispak` и полносистемным `simh`. Сведения взяты из смежных репозиториев
и снабжены ссылками на файлы и номера строк, чтобы каждое утверждение можно
было проверить. Пути ниже указаны относительно `~/Yandex.Disk`, если не
оговорено иное.

Отличие от [emvs/](emvs/): там описаны каналы и связи ЕМВС, здесь — порядок
прогона задач, рабочие сценарии и трассировка.

## 1. Две модели исполнения

| | `dispak` | `simh` (BESM6 / SVS) |
| --- | --- | --- |
| Уровень | интерпретатор экстракодов, мини-супервизор с диска 2099 | аппаратная эмуляция процессора, памяти, дисков, лент, прерываний |
| Задача | колода перфокарт, печать в стандартный поток | задание с перфоленты/терминала, ОС грузится с диска |
| Тома | файлы в каталогах `BESM6_PATH` | образы `attach` к `mdN`, `drumN`, `mgN` |
| Многопользовательность | однопользовательский режим, конкуренции за тома нет | реальная конкуренция задач, захват томов, прерывания |
| Роль | ежедневная отладка и регрессия | системные изменения, загрузка ОС, физические гонки |

Источники: `simh/BESM6/README/README.md:344-368`, `re-dispak/COMMANDS.md:374-399`,
`docs/espd/Сравнение_dispak_и_dubna.red.txt:25-57`,
`re-niti-graph/docs/PHYSICAL-LEVEL.md`.

## 2. Подготовка и запуск

### 2.1. Пакетный эмулятор dispak

Сборка из исходников:

```sh
mkdir build && cd build && cmake .. && make -j$(nproc)
```

(`dispak/README.md:17-21`, `dispak/docs/СБОРКА.md:14-20`, `dispak/AGENTS.md:135-140`;
минимальная версия CMake 3.12 — `dispak/CMakeLists.txt:1`).

Вызов (`dispak/dispak.c:13-16,158-161`, справка `:150-189`):

```
dispak [опции] <task-file>
dispak [опции] <input-buf-number>
dispak [опции] --decode-output <raw-file>
```

Восьмеричное число в argv трактуется как номер входного буфера, иначе это
файл паспорта (`dispak.c:352-366`); очередь ввода —
`$HOME/.besm6/input_queue/NNN` (`dispak/input.c:32-36`, `vsinput.c:783-786`).

Переменные и каталоги:

- `BESM6_PATH` — colon-список каталогов с томами, по умолчанию
  `$HOME/.besm6:/usr/local/share/besm6` (`dispak/disk.c:21,63-76`), поиск
  по элементам `:77-97`; опция `--path` переопределяет список
  (`dispak.c:307-309`).
- эталонные тома 2048, 2053, 2248 (`dispak/AGENTS.md:144-146`);
- `BESM6_FETCH_DISKS=1` форсирует загрузку томов при сборке
  (`dispak/fetch_disk.sh:12-19,26-41`, `dispak/tests/README.md:121-131`);
- `ZERODRUM` и `MD29MB` меняют модель барабана и ёмкость MD
  (`dispak/disk.c:376,419,599`).

Основные опции (`dispak/dispak.c:119-147,163-185`,
`dispak/docs/СПРАВОЧНИК_КОМАНДЫ.md:32-56`): `-x/--native`, `-e/--elfun`,
`-b/--break`, `-v/--visual`, `-t/--trace`, `--trace-e64`, `-s/--stats`,
`--path`, `-p/-q`, `-o`, `--output-raw`, `--decode-output`, `-c`,
`--punch-binary`, `--input-encoding`, `--bootstrap`, `--no-insn-check`,
`--725`, `--coverage`, `--drum-dump`.

Примечание: переменная `DISPAK`, используемая в инструкции СИПРОДа
(`docs/siprod-editor-agent-guide.md:36,44`), в репозитории dispak не
определена; это соглашение координирующего проекта.

### 2.2. Полносистемный эмулятор simh

Сборка только из корня `simh`: `make besm6` даёт `BIN/besm6`; локальный
`BESM6/Makefile` неполный (`simh/CLAUDE.md:11-19`,
`simh/BESM6/README/README.md:39-52`, `simh/BESM6/scripts/build.sh:5-8`).
После сборки автоматически прогоняется `BESM6/tests/besm6_test.ini`
(`simh/BESM6/README/README.md:73`).

Вызов: `besm6 [-flags] [scriptfile ...]`; стартовые `$HOME/simh.ini`, затем
`./simh.ini` (`simh/BESM6/README/README.md:58-102`). Скрипты запускают из
каталога с данными:

```sh
cd ~/Yandex.Disk/simh/BESM6/demo && ../../BIN/besm6 dispak.ini
cd ~/Yandex.Disk/simh/BESM6/tests && ../../BIN/besm6 besm6_test.ini
```

Образы: зоны `8+1024` слов, слово = 8 байт little-endian; `attach -n md06
2052.bin` создаёт образ, номер тома в имени должен быть 2048-4095; `-e`
подключает существующий, `-r` только для чтения
(`simh/BESM6/README/README.md:344-368`). `~` в `attach` не раскрывается,
поэтому тесты копируют образы в рабочую папку как `img-*`
(`simh/BESM6/tests/README.md:40-43`).

Базовый старт: `simh/BESM6/demo/dispak.ini:1-39,190-193` — лог консоли,
барабаны и диски 2052/2053/2063/2048, лента `mg4 es`, принтер `prn0`,
`load boot_dispak.b6`, `run 2000`. Расширенная конфигурация —
`simh/BESM6/OSZAGR/dispak.ini:17-69` (2052, 2148, 2248, 2095, 2063, 2253,
2061, 2070, 2094, 2086, 2073, 2348; ленты 202-214); снимок реального
состояния дисководов — `simh/BESM6/ACPU/output.txt~:125-143`.

Для СВС: `make svs`, затем `SVS/boot.sh` пересобирает рабочие образы перед
каждым прогоном и вызывает `runsim.sh` с сторожем по размеру трассы и
времени (`simh/SVS/boot.sh:3-34,44-56,89-90`, `simh/SVS/runsim.sh:2-22,25-48`).

## 3. Порядок прогона задачи

### 3.1. Колода для dispak

Структура: паспорт + наборы данных + терминатор (`dispak/Input-Format:1-9`).

Ключи паспорта принимаются русскими или английскими (`dispak/vsinput.c:158-387`):
`ШИФР/USE` (`:158-200`), `ВХО/BEG` (`:248-256`), `АВОСТ` (`:257-259`),
`АЦП/LPR` (`:261-269`), `ТЕЛ/TEL` (`:271-275`), `СПЕ/SPE` (`:277-281`),
`ОЗУ` игнорируется (`:283-285`), `ВРЕ/TIM`, `ТРА/TRA`, `ЛИС/PAG`
игнорируются (`:287-300`), `РОС/WRI` (`:302-305`), `ФИЗ/PHY`
(`:307-318`), `ЛЕН/TAP` и `ДИС/DIS` (`:320-375`). Неизвестная строка
печатается как `Unknown passport entry` (`:376-381`).

Элементы данных: `S` (адрес загрузки, первым) — `Input-Format:76-79`,
`C` (9/18 октальных цифр) — `:81-84`, `W` (данные) — `:86-88`, `N`
(число) — `:90`, `L` (6 литер) — `:92-94`, `A0/A1/A2` (текст до `_$`)
— `:96-99`, `A3` (бинарные карты) — `:101-102`, `E` (конец набора) —
`:104`. Парсер: `GOST_B` (`:423-429`), `GOST_C` (`:430-435`),
`GOST_K` (`:436-460`), `GOST_BE` (`:461-477`), `GOST_A` (`:483-522`),
`A3/A5` (`:523-596`).

Терминатор: `FINISH` по документации (`Input-Format:106-108`), фактически
`E` + `КОНЕЦ` или `FINISH` (`vsinput.c:605-635`); примеры —
`dispak/tests/pprog01/pprog01.b6:53`, `dispak/docs/СБОРКА.md:101`.

Звёздочные карты `*...` — Director/комментарии транслятора внутри колоды
(`dispak/tests/pprog01/pprog01.b6:18-30`), `*END FILE` как граница
(`dispak/dispak/extra.c:3392,3401`).

### 3.2. Задание Монитора-80

Управляющие карты разбираются таблицей `SWITCH`; формат `*ИМЯ
[параметры]`, имя до 6 литер
(`monitor80-re/docs/СПРАВОЧНИК_КОМАНДЫ.md:310-410,467-477`). Задание =
паспорт, системные карты, данные, терминатор (там же `:480-489`,
`:519-524`). Пример паспорта: `ШИФР 410301^`, `ОЗУ 512K^`, `ВХО 1^`,
`ВРЕ 001000^`, `START 1000^`, `E` (там же `:491-517`).

Карты `*PERMANENT`, `*TEMPO`, `*NO LOAD` (там же `:43-51,297-310`),
`*CALL`, `*EXECUTE`, `*END FILE`, `*READ`, `*EDIT`, `*NAME`
(там же `:88-102,364-395`). Трансляторы `*ASSEM`, `*FORTRAN`, `*FTN`,
`*BEMSH`, `*PASCAL`, `*FOREX` (там же `:105-125`). Типичные ошибки —
`ОШИБКИ В КАРТЕ '47'`, `NO *END FILE` (там же `:669-680`).

Минимальный рабочий пример для транслятора БЕМШ:
`re-bemsh/tools/trace-translator.sh:43-75` (паспорт `шифр 419999^`,
`лент 30(2048-6200)^`, `лент 42(2099)^`, `лент 43(2248-ЗП)^`, карты
`КВЧ`, `ТРН`, `ЧТКОМП420070^`, `ЗОНМОД433900 0001^`, `ЕКОНЕЦ`); перед
прогоном копируются тома 2048, 2053, 2099, 2248 (там же `:17-40`),
запуск `dispak -l -tt "$JOB"` (там же `:98-105`).

### 3.3. Подача задания в simh

Сквозной пример: `simh/BESM6/demo/punchtape.ini:1-36` — `at -t fs0
input.txt`, ожидание `СМ1П`, `do dispak.ini`, `set cpu req`, подача колоды,
ожидание `КЗ`, повторный запрос для включения принтера, результат в
`output.txt`. Колода: `simh/BESM6/demo/input.txt:1-53` (`ШИФР 419999 ЗС5^`,
`*ASSEM`, `*FTN`, `*EXECUTE`, `*END FILE`, `ЕКОНЕЦ`).

В СВС сценарий подключается симлинком `scenario.ini` к `svs.ini`:
`svodka.ini` (`expect "СМ1П"` → `СВОДКА 4199`, `СБО А0`, `ДАЙ А1`),
`arfa_regions.ini`, `starfa_rights.ini`, `hybrid.ini`
(`simh/SVS/svs.ini:184-191`, `simh/SVS/svodka.ini:1-17`,
`simh/SVS/arfa_regions.ini:11-63`, `simh/SVS/starfa_rights.ini:1-26`,
`simh/SVS/hybrid.ini:1-42,64-88`).

### 3.4. PERSO-библиотеки и компиляторы

Конвейер Pascal-Монитор: `pascompl.b6` компилируется под Монитором-80
в dispak, объект `PASCOMPL` записывается в PERSO тома 2348
(`pascal-re/PERSO.md:3-9`). Механика: `лен LU(ТОМ-wr)^` монтирует том,
`*PERSO:LUZZZZ` читает библиотеку, `,CONT` дозаписывает, `*TO PERSO:LUZZZZ`
пишет обратно; зоны Монитора восьмеричные, `besmtool` — десятичные
(там же `:46-62`). Скрипты `init-disk-2048.sh`, `perso-build.sh`,
`perso-check.sh`, `perso-run.sh` (там же `:66-161`).

На томе 2348: PERSO `02570` с программами 203 (`re-dispak/rukava.be:2963-2967`),
ГЛИССАДА-6 в зоне `2700` (там же `:24,27,3216-3222`), Фортран-порт ГРАФОР
в зонах `3050..3240` (там же `:3246-3261`). Вызов из PERSO:
`*PERSО:402700 ; *PERSО:402570,CONT ; *CALL GLDIAL`.

## 5. Особенности выполнения отдельных задач

- **Мини-супервизор dispak.** Команда `ВЫПР (М16)` `16 32 ХХХХХ`:
  `40142` отладочный останов на следующей команде, `40160` выдача на АЦПУ,
  `40163` статистика, `40166` состояние регистров, `40164` трассировка,
  `40170` выполнение экстракодов супервизором
  (`dispak/Mini-Supervisor.txt:63-87`); старт с 00010, экстракоды → 00011
  (там же `:54-57`). Исходники супервизора на диске 2099 (там же `:104-118`).
- **Экстракоды ОС.** `Э050`, `Э063`, `Э070` —
  `re-dispak/docs/Dispak-programmer-guide.md:2048-3900,6358-8102,8464-8489`;
  таблица перехваченных экстракодов — `re-dispak/rukava.be:3067-3134`.
- **Паспорта и ключи.** Стандартные паспорта в зонах `0543-0544`, копия в
  `0443-0444`; ключи диалоговых систем в `0675`, копия в `0445`
  (`re-dispak/rukava.be:2653-2656,2706-2712,2783-2786`).
- **Отладчик ОС.** НРОТ `0573` вызывается по разделу паспорта теле,
  отладчик ОС — зона `0610` (там же `:2732-2747`).
- **Конкуренция за тома** в dispak отсутствует; системные гонки проверяются
  на simh (`docs/toolkit.md:118-120`).
- **MONSYS.9** в дереве `simh` отсутствует; полный ДИСПАК там грузится через
  `boot_dispak.b6`, а лента MONSYS.9 относится к эмулятору Дубны
  (`docs/espd/Сравнение_dispak_и_dubna.red.txt:30,168,174`).

## 6. Трассировка: физический уровень и уровень ОС

### 6.1. Физический уровень simh

- BESM6: `set cpu debug` — полный трассер; `set mmu debug`, `set drum debug`,
  `set md0 debug`; категории MD `OPS`, `RRD/RWR`, `INTERRUPT`, `TRACE`,
  `DATA`, `STATUS` (`simh/BESM6/README/README.md:551-566`). Вывод:
  `set -n console log=log.txt`, `set console debug=log`, `set debug "out.trace"`
  (там же `:568-579`). Пример `set cpu debug; dep PC 32000; step 20`
  (там же `:581-592`).
- Содержимое трассы: команда с адресом и октальными полями, изменившиеся
  регистры, `Memory Read/Write`, исключения (там же `:596-640`).
  `set cpu nodebug` выключает; полная трасса дорогая, лучше `step`/breakpoint
  (там же `:651-665`).
- `set pult=N`: `11` экстракоды и ПВ, `15` детальная трасса команд, `17`
  максимум; формат `СчАС: КОП адрес [ИР] результат`
  (`simh/BESM6/README/COMMANDS.md:326-380,399-414`).
- SVS: куда писать (`set debug <file>`, `-n`, `log`, `stdout`) и что
  (`cpu0..cpu3`, флаги `INSN`, `EXTRA`, `REGS`, `FETCH`, `DEV`) —
  `simh/SVS/Tracing.md:9-19,23-45,49-74`. Окно адресов
  `set cpu0 window=76000:77777` (там же `:78-96`). Рецепты: `debug=dev`
  (~3 МБ/с), `debug=extra` как дешёвый call-trace (там же `:241-276`).
  `set cpu0 debug` без открытого debug-файла молча ничего не даёт
  (там же `:280-303`).

### 6.2. Уровень ОС

- `dispak -t` увеличивает уровень трассировки, `-tt` печатает каждую
  исполненную команду
  (`re-bemsh/docs/DYNAMIC-TRACE.md:15-42`); `-b`/`-v` дают интерактивный
  отладчик `breakpoint/b/trace/where/step/execute/bpw`
  (там же `:44-50`). Поток: `dispak -l -tt … 2>&1 >listing |
  python3 agg-dynamic.py >zones` (там же `:87-100`). Ограничение:
  `abpc` — 15 бит, зона ≤ `037₈`, обратного соответствия дисковой зоне
  0137-0177 нет (там же `:174-221`).
- CLI dispak: `-s/--stats` (`dispak.c:129,264-266,413-418,516-533`),
  `--trace-e64` (`:127-128,304-306`), `--coverage` (`:145,319-321`),
  `--drum-dump=file` (`:146,322-324,421-430,552-619`),
  `--output-raw`/`--decode-output` (`:135-136,283-289,331-336,490-508`).
- Переменные отладки dispak: `BESM6_DD_DEBUG` (дампы Э70/Э50/Э62,
  `cu.c:22-30`, `extra.c:36-43`, `vsinput.c:22-30`),
  `BESM6_WATCH`/`BESM6_WATCH_RW` (`cu.c:478-510`),
  `BESM6_NITI_DEBUG` (`extra.c:167-171`), `BESM6_ARFA_DEBUG`
  (`arfa.c:1150,1352`).
- `re-dispak/COMMANDS.md`: «ПРОАНАЛИЗИРУЙ ТРАССУ», «СРАВНИ ТРАССЫ»,
  «ПОКАЖИ РЕГИСТРЫ В <АДРЕС>» (`:214-269`); запуск
  `../../BIN/besm6 dispak.ini`, `set pult=N`, `run`, Ctrl+G (`:329-350`);
  формат трассы `:401-450`.
- СИПРОД: `tools/siprod_trace.py` (`re-siprod/SIPROD.md:529-539`),
  трассировка ветвей в `re-siprod/notes/commands.md:1-6`.

### 6.3. Стык уровней

`simh/BESM6/doc/ЭК-ТРАССИРОВКА.md:1-40`: `cpu.log` (флаг
`GPSTAR_CPU_DEBUG=1` → `set cpu debug`) содержит вход в экстракод
(`*** TRACE GP-EK050 PC=… Aex=…`), а `debug.log` (`set debug`) — guest-трассу
диспетчера (`01243 R: 00 050 1210 э50 1210 = 1210`). Цепочка
`ЭКЛИСТ → БОЭК1 → ТИВ → нерезидент` прослежена там же `:42-70`.
Слоги МПД СВС трассируются устройством `cpu0 --- МПД линия 75: символ 160`
(`simh/SVS/МПД.md:1-45`).

## 8. Оговорки

- Часть сведений взята из описаний проектов без повторного прогона
  эмулятора; если эмулятор не запускался, это указано в источнике.
- `ctest -N` в dispak показывает 52 теста (`tests/CMakeLists.txt:1-57`),
  тогда как документация называет 51 (`docs/СБОРКА.md:39`, `AGENTS.md:139`).
- `simh/BESM6/demo/dispak.ini:48-57,71-100` содержит неразрешённые
  merge-конфликт-маркеры; перед использованием файл нужно проверить.
- Документация по `set pult` расходится (`BESM6/README/COMMANDS.md:326-380`
  против `BESM6/README/README.md:288`); режимы нужно уточнить по коду.
- Раннеры `re-niti-graph` и `re-bemsh` проверяют низкий уровень, но не
  заменяют полный прогон под ДИСПАК.
