# Значения опкодов БЭСМ-6 020, 021, 033, 036, 046, 047 — ЛОКАЛЬНЫЕ источники

Дата: 2026-11-19.

> **ФИНАЛЬНАЯ КОРРЕКЦИЯ (2026-11-19, перекрывает выводы ниже).** Наши машинные слова имеют **бит 20 = 0 ⇒ SHORT (первый тип, `CmdSheet.md:17`)**, а не LONG (`CmdSheet.md:96` — второй тип, бит 20 = 1). В `besm6tape.py:84` стоит `is_long = (h >> 19) & 1` — **off-by-one баг**: проверяется бит 19 вместо бита 20, поэтому он даёт **ошибочный `is_long=1` из-за бита 19**. Все прежние выводы «в нашем коде LONG», «Additional system call», «flush BRZ» и «втбрз» для наших слов недействительны: `втбрз` — имя подпрограммы `gens1.be`, а не мнемоника opcode. Корректные SHORT-значения: 020=`сбр`/`APX`, 021=`рзб`/`AUX`, 033=`увв`/`EXT`, 036=`сда`/`ASN` (сдвиг на N−64), 046/047=незаконные/не используемые (`disbesm6.c:61,62,72,75,83,84`).

Режим: только чтение + один выходной файл (`src/`, `include/`, `REFERENCE` не изменены).
Дополняет `11-opcode-meanings-web.md` (веб-исследование); здесь — только то, что лежит на диске.

## 0. Главное: один номер = две разные команды

Локальные источники единодушны: БЭСМ-6 имеет **два формата** 24-битной команды, и opcode
сам по себе не определяет команду — нужен признак формата (бит 20):

> «Команды consist из номера индекс-регистра, кода операции и кода адреса.
> Выделяют два типа команд: с коротким 12-ти разрядным адресом / с полным 15-ти разрядным адресом.
> Команды первого типа (20-й бит "0") … Команды второго типа (20 бит "1")»
> — `/home/azizz/besm6.github.io/wiki/CmdSheet.md:6-21, 96-103`

Поэтому **020/021/033/036 в коротком формате — совсем не то, что 20/21/33/36 в длинном**.
046/047 существуют только в первом (коротком) формате.

Проверено по машинным словам из аннотаций (`FOREX_CORE.mad`, `LO_SYN.mad`, `test_cu.b6`):
маска `disbesm6.c:0x0f8000` даёт для `,*20,` → `0o20`, для `,*36,` → `0o36`,
т.е. **`*20`/`*21`/`*36` в разбираемом коде — это ДЛИННЫЙ формат** (подробности §4).

## 3. `втбрз` — специальная проверка (главный вопрос пользователя)

**Вывод: «втбрз» НЕ является названием машинной команды.** Это **имя процедуры (метки)
в исходнике ДИСПАК** `gens1.be`, и в дизассемблерах оно ошибочно использовано как мнемоника.

`/home/azizz/Yandex.Disk/re-dispak/gens1.be:1440-1450` — дословно:
```
1440: ***************************************************
1441: * ВТБРЗ – ВЫТАЛКИВАНИЕ БРЗ И ВОЗВРАТ               *
1442: ***************************************************
1443: втбрз   уиа     -6(М15)    , М15 := -6 (цикл по 7 регистрам БРЗ)
1444: втбрз1  зп      1          , записать 0 в БРЗ (вытолкнуть содержимое)
1445:         мода    втбрз1    , модифицировать адрес следующей команды
1446:         цикл    (М15)      , цикл по М15 (выполнить 7 раз)
1447:         рег     '20'       , записать 0 в регистр приписки 0
1448: * (сброс приписки после работы с БРЗ)
1449:         уи                  , сброс модификации адреса
1450:         пб      (М17)      , возврат по адресу в М17
```
`/home/azizz/Yandex.Disk/re-dispak/gens1.be:1556-1558`:
```
1556: * Вызов процедуры сброса БРЗ (втбрз) для очистки
1557: * буферных регистров записи перед продолжением.
1558:         пв      втбрз(М17)  , вызов втбрз, адрес возврата в М17
```
То есть `втбрз` — это подпрограмма, вызываемая командой `ПВ` (VJM), и расшифровывается
как **«ВЫТАЛКИВАНИЕ БРЗ И ВОЗВРАТ»**, где БРЗ = буферные регистры записи (см. Тюрин выше).
Гипотеза «выбор/установка базового регистра» **опровергнута**:

- `rukava.be` и `CmdSheet.md` не содержат строки «втбрз»;
- авторитетные таблицы называют длинный opcode 36 «э36» / «*36» / «тоже что и э34» /
  «free operation code», но **никогда «втбрз»**;
- ближайший авторитетный факт — задокументированный в оригинальном руководстве
  побочный эффект **«flush BRZ»** у длинного 036 (`Besm6_Instruction_Set.md:1298-1299`),
  что по смыслу совпадает с именем подпрограммы «выталкивание БРЗ», но не тождественно ей.

**Итог:** имя «втбрз» в `besm6tape.py:49`, `disbesm6.c`-аналогах и `svs_sys.c:55` —
плейсхолдер/заимствование из имени подпрограммы, **не подтверждённое название команды**.
Правильно маркировать как «ненадёжное имя дизассемблера».

## 4. `*20`/`*21` — специальная проверка

Уточнение пользователя («пары `*20`↔`э20`, `*21`↔`э21` ошибочны») требует оговорки:
**как мнемоники из дизассемблера они действительно не являются семантическими именами,
но сами обозначения `э20`/`э21` в авторитетных источниках существуют** — это не выдумка
`besm6tape.py`. См. `rukava.be:101`, `CmdSheet.md:107-108`, `Bemsh.md:562-563`,
`Besm6_Instruction_Set.md:1054-1055`, `besm6-commands.md:316`.

Что подтверждено:
- длинный 20/21 = **экстракоды / дополнительные системные вызовы** (класс команды);
- по `э20`/`э21` нет отдельного описания в `rukava.be` (нет строк 21 и 36) и пустое
  описание в `CmdSheet.md:108` — то есть **конкретное назначение (какой именно системный
  вызов) в локальных источниках НЕ найдено**.

Что НЕ подтверждено:
- «ввод/вывод слова», «пересылка», «установка режима» — ни одного такого описания для
  длинных 20/21 в локальных источниках нет. Управление вводом-выводом — это **короткий 033 (увв)**,
  а не `*20`/`*21`.
- (Для коротких 020/021 это вообще битовые операции сбр/рзб.)

Проверка по реальным машинным словам (декодирование маской `0x0f8000` из `disbesm6.c`):
```
Слово 22040513 (из LO_SYN.mad, аннотация 4,*20,EX4051) → opcode 0o20, addr 0o40503
Слово 23675551 (из LO_SYN.mad, аннотация 4,*36,EX7555) → opcode 0o36, addr 0o1671541
Слово 12000100 (из wiki/simh/test_cu.b6:180, «э20 100(2)») → opcode 0o20, addr 0o100, idx 2
```
⇒ в разбираемом коде `*20`/`*21`/`*36` — **длинный формат**, так что применима колонка §1.2,
а не «сбр/рзб/сда». (Файлы `LO_SYN.mad`, `FOREX_CORE.mad`, `lib21/` сейчас лежат в
`/home/azizz/.local/share/Trash/files/extract-stale-selftest-822462/src/`; цитаты выше
взяты оттуда же.)
