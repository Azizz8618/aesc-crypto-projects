# Инструкция для агента: оформление документации редактором СИПРОД-П (`*RED`)

Настоящая инструкция описывает, как подготовить текст, отформатировать его
редактором СИПРОД-П (РЕДÀКТ) и сохранить результат в виде, принятом в проекте.
Образец — `docs/espd/План_внедрения_блочного_шифрования_задание_3.b6` и его
печать `docs/espd/План_внедрения_блочного_шифрования_задание_3_печать.txt`.

## 1. Когда применять

Редактор используется для документов ЕСПД: пояснительных записок, отчётов,
программ и методик испытаний, описаний применения. Результат — печать на АЦПУ
(текст с рамками, номерами страниц, штампом и таблицами), которую можно
перевести в PDF. Для обычных заметок в Markdown редактор не нужен.

## 3. Окружение и запуск

Обязательные переменные:

```sh
export DISPAK=/usr/local/bin/dispak
export BESM6_PATH="$HOME/.besm6:/usr/local/share/besm6"
```

Рабочий путь — компиляция из исходника (требуется том 2348 с библиотекой
Паскаля в зоне 2570(8)):

```sh
cd ../re-siprod/pascal
DISPAK=/usr/local/bin/dispak BESM6_PATH="$HOME/.besm6:/usr/local/share/besm6" \
    scripts/прогнать.sh source/redakt.pas /путь/к/разметке.txt > /путь/к/печати.txt
```

Сценарий сам отделяет выдачу задачи (между эхом `*ЕХЕСUТЕ` и `КОНЕЦ ЗАДАЧИ`),
поэтому в перенаправленный файл попадает только печать.

Быстрый путь (без компиляции) применим, только если на томе 2348 записана
библиотека зоны 2150(8) — проверьте её наличие командой
`scripts/прогнать-с-тома.sh redakt <файл>`; при ответе `ОТСУТСТВУЕТ RЕDАКТ`
пользуйтесь предыдущим путём. Запись зоны 2150 выполняется сценарием
`pascal/scripts/запись-2348.sh` на **рабочей копии** тома.

Для сверки с исходным СИПРОДом:

```sh
../re-siprod/tests/siprod/run.sh /путь/к/разметке.txt
```

Правило: боевой образ `/usr/local/share/besm6/2348` не изменяется; все записи
делаются на копии в `$HOME/.besm6`.

## 4. Подготовка текста

1. **Одна строка = одна перфокарта.** Длина строки — не более 80 символов.
   Более длинные строки вызывают «БЫЛИ ОШИБКИ ВВОДА / БЫЛИ ОШИБКИ ПРИ
   ТРАНСЛЯЦИИ ИЛИ В НАБИВКЕ». Рвите фразу на карты заранее, по словам.
2. **Кодировка ГОСТ-10859.** В наборе нет литеры Ё и строчных букв.
   Нормализацию (`Ё → Е`, `« » → "`, `— / – → -`, `… → ...`, верхний регистр)
   выполняют `прогнать-с-тома.sh` и `собрать-колоду.sh`.
   Сценарий `прогнать.sh` текст **не нормализует** — подайте ему уже
   подготовленный файл:
   `sed 's/[ёЁ]/Е/g; s/[«»]/"/g; s/—/-/g; s/–/-/g; s/…/.../g' текст | tr '[:lower:]' '[:upper:]' > подготовленный`.
   Ё в исходнике допустима: новый редактор печатает на её месте Е, тогда как
   исходный СИПРОД теряет литеру целиком (см. `red-эталоны/README.md`).
3. **Табуляции недопустимы**, только пробелы. Символ `*` в начале строки —
   начало команды, в конце карты `*` опускается.
4. Блок разметки начинается картой `*RED` и заканчивается `*E`, после всех
   блоков ставится `*END`. Блоков может быть несколько (титул, содержание,
   основной текст) — нумерация страниц сквозная.
5. Команды пишутся слитно: `*0STA*RG*254N*1RL*0MCS5 63`. Число перед командой
   по умолчанию равно 1; `*0` обычно означает отмену.

## 5. Быстрая справка по командам `*RED`

| Команда | Действие |
| --- | --- |
| `*nS` | новый абзац с отступом, `n−1` пустых строк перед ним |
| `*n/` | перевод строки, `n−1` пустых строк |
| `*nP` | конец страницы (`*3P` — две пустые страницы) |
| `*Tтекст` | заголовок по центру + 2 пустые строки |
| `*MDтекст` | центрированная строка без пустых строк |
| `*D` | остаток карты как есть (рисунки, `*/*D…`) |
| `*nH` | следующие `n` литер как есть (`*H*` — литера `*`) |
| `*nG`, `*nC<c>`, `*Knc`, `*nF<c>`, `*nRF<c>` | позиция, повтор литеры, заполнение |
| `*n(текст)` | повтор текста до `)` `n` раз |
| `*nRL`, `*nRC`, `*OLR`, `*RT` | интервал, разрядка, режим «как есть», обычный перенос |
| `*RU`, `*ORU` | широкий формат / возврат |
| `*RG` | рамка вокруг страниц (со следующей страницы) |
| `*nSTA`, `*nSTO` | формат А / обычный формат |
| `*0STPтекст`, `*0STGтекст` | штамп под номером страницы / подвал |
| `*nMCS a w`, `*nMCP a b` | левое поле и ширина строки / размеры страницы |
| `*nN`, `*NN` | номер следующей страницы / подавить нумерацию |
| `*ST a1 b1 …`, `*SL …` | таблица без линеек / с линейками |
| `*nM=тело$`, `*nM` | определить и вставить макро |
| `*MF … ///` | листинг программы как есть |
| `*E`, `*END` | конец блока `*RED`, конец задания |

**Таблицы:** после `*ST a1 b1 a2 b2 …` каждая карта начинается с ` k)`
( k — номер колонки), `$` в первой позиции завершает таблицу. Позиции
считаются от левого поля и должны укладываться в ширину строки (иначе
ошибка 64). Продолжение ячейки — карта без `k)`.

**Правила вёрстки таблиц, проверенные на отчёте о dispak и dubna.**
После исправлений R‑01..R‑04 в `re-siprod` (коммит `bbd6107`) эти меры
стали **не обязательными**, но остаются допустимыми и безопасными:

1. Для таблицы **с границами** используйте `*SL`, а числа в ней — это
   позиции линий, не пары границ. Для трёх колонок в поле `*0MCS5 63`
   подходит `*SL 1 22 43 63`. Таблица без линеек задаётся `*ST 1 21 22 42 43 63`.
2. Текст ячейки должен быть **короче ширины колонки**. Если он заполняет
   колонку точно, соседние колонки слипаются. Укорачивайте надпись, а не
   расширяйте поле сверх `*0MCS5 63`.
3. В блоке с таблицей обязательно ставьте `*0RL`. Режим `*1RL` **сохраняется**
   из предыдущего блока `*RED` и добавляет пустые строки между строками
   таблицы; одним удалением `*1RL` из заголовка дело не исправляется.
4. Таблицу выносите в **отдельный блок `*RED`**: сразу после `$` ставьте `*E`.
   Если в том же блоке после таблицы идёт заголовок `*T` или длинный текст,
   редактор перемешивает строки таблицы и текста. Дописывать `*P` перед
   заголовком нельзя — это усугубляет наложение.
5. Первый абзац после таблицы начинайте **обычным текстом**, без `*S`.
6. После сборки обязательно **смотрите печать**: слипшиеся или перемешанные
   строки видны сразу, даже если `ERROR NR.` не было.

Рабочий пример — `docs/espd/Сравнение_dispak_и_dubna.red.txt`.

**Выделение пунктов и подчёркивания.** В отчёте о dispak и dubna
применены три макроса-маркера и подчёркивания `^`:

| строка разметки | печать |
| --- | --- |
| `*1M==+$` | `=+` — мар первого уровня |
| `*2M===+$` | `==+` — мар второго уровня |
| `*3M=*D*D* $` | `*D*` — мар третьего уровня |

Правила вызова, проверенные на отчёте:

- макрос вызывается **отдельной картой**, перед ней ставится `*S`
  (иначе маркер прилипает к предыдущей строке);
- в теле макроса **нельзя оставлять пробел на конце** — пробел
  добавляется в вызове или в теле только у `*3M`;
- `*3M` использует литеральный режим `*D`: через `*H*D*H*` маркер
  терялся в последующих блоках.

Подчёркивание: `*63C^` даёт линию из `‾` под заголовком (для поля
`*0MCS5 63`), `*56C^` — для титульного блока. Ключевое слово
подчёркивается последовательностью `\^` **сразу после слова**;
пробел вставлять нельзя, иначе слово рвётся.

**Первая карта блока** разбирается особо (FIRCAR): `*RG`, `*RU`, `*nN`, `*NN`,
`*nST…` в ней действуют немедленно. Типовой заголовок:

```
*RED
*0STA*RG*254N*1RL*0MCS5 63
*0STPСУНЦ.УЭВС.00.00.01 ПЗ
```

## 6. Шаблон документа

```
*RED
*0STA*1RL
*4/
*MD<ОРГАНИЗАЦИЯ>. ОТЧЁТ
*4/
*T<ИЗДЕЛИЕ>. <ВИД ДОКУМЕНТА>
*3/
*MD<НАЗВАНИЕ ДОКУМЕНТА>
*3/
*MD<ПОДЗАГОЛОВОК>
*4/
*MD2026
*E
*RED
*0STA*RG*1RL*0MCS5 63
*0STP<ОБОЗНАЧЕНИЕ ДОКУМЕНТА>
*T1. <РАЗДЕЛ>
*S<ПЕРВЫЙ АБЗАЦ>
<ПРОДОЛЖЕНИЕ АБЗАЦА, КАРТА НЕ ДЛИННЕЕ 80 СИМВОЛОВ>
*S<ВТОРОЙ АБЗАЦ>
*E
*END
```

Заголовки разделов нумеруются через `*T` или `*S` (как в образце), таблицы —
через `*ST`. Для схем ДРАКОН использовать блок `*DRK` (встроенный режим) или
отдельный `drakon.pas`, согласно `pascal/README/README.md`.

## 7. Ошибки и диагностика

Ошибка печатается как `ERROR NR. n` + `ОБРАЗ ПЕРФОКАРТЫ:` и останавливает
задачу. Основные коды: 10 — неизвестная команда; 20 — нет числа; 30, 40 —
число вне диапазона; 61, 62, 64, 66 — таблицы (64 — позиция за шириной строки,
66 — после `*ST` нет карты ` k)`); 80 — нет места на строке; 91 — макро;
100 — неизвестный блок.

Если вместо печати получено сообщение об ошибках ввода или трансляции, почти всегда
виновата карта длиннее 80 символов. Полный журнал для диагностики:

```sh
( cd /tmp/работа && DISPAK=... BESM6_PATH=... dispak job.b6 )
```

Колоду `job.b6` для ручного прогона строит `scripts/собрать-колоду.sh`, либо
её можно взять из готового задания в `docs/espd/`.

## 8. Что и где сохранять

| Файл | Содержимое |
| --- | --- |
| `docs/espd/<имя>.red.txt` | исходная разметка `*RED` (редактируемый источник) |
| `docs/espd/<имя>.b6` | готовая колода задания для dispak (как образец) |
| `docs/espd/<имя>_печать.txt` | печать АЦПУ — результат работы редактора |
| `docs/espd/<имя>.pdf` | PDF (если требуется): `scripts/печать-в-пдф.py <печать.txt>` |

После сохранения добавить ссылку на документ в `README.md` или `STATUS.md`
координационного проекта.

## 9. Чек-лист перед сдачей

1. Все карты ≤ 80 символов, нет табуляций. Ё в исходнике допустима, но
   перед подачей в `прогнать.sh` вход нормализуется по ГОСТ‑10859.
2. Каждый блок `*RED` закрыт `*E`, в конце стоит `*END`.
3. В таблицах есть `$` и корректные `k)`, позиции в пределах ширины,
   текст ячеек короче колонок.
4. Таблица вынесена в отдельный блок `*RED`, в нём явно стоит `*0RL`,
   сразу после `$` идёт `*E`.
5. Прогон завершён без `ERROR NR.` и без сообщений об ошибках ввода.
6. Печать просмотрена **глазами**: нет наложений строк и пустых строк
   внутри таблиц; абзацы, заголовки и номера страниц на месте.
7. Сохранены три файла: разметка, колода, печать; ссылка добавлена в docs.
