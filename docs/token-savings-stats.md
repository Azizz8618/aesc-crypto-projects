# Статистика экономии токенов в текущих сессиях

Дата сбора: 25.11.2026. Источники — локальный учёт `ccusage` 20.1.2
(`ccusage opencode daily --json`, `ccusage daily --json`) и `tokcount` 0.14.0
(`tiktoken`). Сырые выгрузки сохранены вне репозитория в `/tmp/osint_ai/`,
в документ попадают только агрегаты.

Документ дополняет [cost-optimization.md](cost-optimization.md): там методика
описана, здесь приведено фактическое состояние сессий на дату сбора.
Формулы расчёта эффективности решения задач — в
[repeated-read-efficiency.md](repeated-read-efficiency.md).

## 1. Что считается экономией

- `cacheRead` — токены контекста, прочитанные из кэша вместо повторной
  отправки тех же данных как свежего ввода.
- Экономия в токенах = `cacheRead`: столько токенов не пришлось отправлять
  заново.
- Доля кэша в контексте = `cacheRead / (input + cacheRead)`.
- Множитель = `(input + cacheRead) / input`: во столько раз больше контекста
  обрабатывается на один свежий токен.
- `cacheCreate = 0` во всех периодах: новый кэш в этом контуре не создаётся,
  поэтому методика работает только на уже прогретом кэше.
- Бесплатные модели помечены в `ccusage` как `unpricedModels`, их цена равна 0.
  Поэтому экономия выражена в токенах, а не в деньгах.

## 7. Оговорки

1. `totalTokens` в `ccusage` больше суммы четырёх показанных категорий
   примерно на 0,22 %: дополнительная категория не разобрана в выгрузке.
   Все доли в разделах 2–4 считаны по сумме четырёх категорий.
2. Бесплатные модели не имеют цены в `ccusage`, поэтому `$0` в расходе
   не означает нулевую нагрузку на контекст.
3. `cacheCreate = 0` у OpenCode: экономия достигается повторным чтением
   существующего кэша, а не созданием нового.
4. Показатели снимаются на дату сбора и меняются после каждой сессии;
   для сравнения используйте ту же команду и тот же набор категорий.
