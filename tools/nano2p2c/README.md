# nano2p2c

Мост от языка NanoLang к диалекту P2C компилятора pas2c для БЭСМ-6.
Инструмент не заменяет компиляторы: он понижает уже сгенерированный NanoLang
код на C до того подмножества C-подобного языка, которое принимает `pas2c`.

## Конвейер

```
example.nano
  |  nanoc --target c
  v
program.c          (hosted C99/C11, int64_t, <stdint.h>, runtime helpers)
  |  nano2p2c.py
  v
program.p2c        (целочисленный диалект P2C, sizeof в словах, main как void)
  |  sed + base (pas2c)
  v
program.o          (объектный модуль БЭСМ-6)
  |  reconstruct-bin-header.py wrap
  v
program.bin        (PERSO-модуль Дубны)
  |  dubna / dispak
  v
результат программы
```

`pas2c` не является компилятором C11: он компилирует C-подобный язык P2C,
порождая модули в формате Дубны. Отдельный C11-компилятор лежит в
`besm6-new/c-compiler` и требует своей сборки; этот мост нацелен именно на
`pas2c`, как указано в задаче.

## Соответствие диалектов

| C из NanoLang | P2C | Примечание |
| --- | --- | --- |
| `int64_t`, `size_t` | `int` | одно слово БЭСМ-6 |
| `uint8_t` ... `uint64_t` | `unsigned` | нижняя половина умножения |
| `INT64_C(7)`, `UINT64_C(7)` | `7`, `7U` | литералы P2C |
| `(long long)(expr)` | `(expr)` | приведение не нужно |
| `printf("%lld\n", ...)` | `printf("%d\n", ...)` | вариант P2C |
| `nano_cb_N_entry()` | `nano_entry()` | точка входа |
| `int main(void)` | `void main(int argc, char **argv)` | точка входа P2C |
| `int total = 0;` в теле функции | `int total;` и `total = 0;` перед операторами | P2C требует объявлений в начале блока |

Служебные функции `nano_cb_*` (binary64-защита, работа со строками,
управление памятью) не переносятся: в целочисленном подмножестве они не
используются. Если вызов такой функции остался в программе, инструмент
отказывает, а не выпускает модуль с неопределённым идентификатором.

Диапазон: знаковый `int` P2C занимает 41 бит (−2⁴⁰ … 2⁴⁰−1),
`unsigned` — 48 бит (`besm6-new/c-compiler/docs/Besm6_Data_Representation.md`).
Литералы вне знакового диапазона вызывают отказ, а не молчаливое усечение.

Поддерживаемое подмножество: целочисленные литералы и арифметика
(`+`, `-`, `*`), отрицательные результаты, `println` целых и строковых
литералов, прямые и взаимные вызовы посредством `if/else`, локальные объявления с
инициализаторами и циклы `while` без глобального состояния.

## Явные отказы

Инструмент останавливается с диагностикой, если в program.c встречаются:

- `double` / `float` (не поддерживаемый binary64 мост);
- строковые значения как величины (`const char *`, `char *`) и хелперы текста
  NanoLang (строковые литералы, переданные непосредственно в `printf`,
  допустимы и переносятся как есть);
- `struct`, `union`, `void *`;
- вызовы host runtime (`malloc`, `free`, `atexit`, `snprintf`, `sprintf`);
- файловые и FFI-вызовы (`fopen`, `dlopen`, `dlsym`);
- оставшиеся вызовы служебных функций `nano_cb_*` (например, глобальное
  состояние NanoLang порождает `nano_cb_0_init()`, который в P2C не определен);
- `str_length` → `strlen`: в P2C нужен явный assembler-прототип, который
  инструмент не выпускает;
- `assert` в обычном коде → `fprintf(stderr, ...)` и `exit(1)`: в P2C
  предопределён только `printf`;
- целочисленные литералы, превышающие 41-битный знаковый диапазон.

Отказ считается корректным результатом: мост не выпускает модуль, семантику
которого он не может подтвердить. Для других типов нужен отдельный
контракт понижения, а не молчаливая подстановка.

## Проверка

```sh
cd /home/azizz/Yandex.Disk/aesc-crypto-projects/tools/nano2p2c
sh run-e2e.sh
```

Скрипт печатает сгенерированный P2C, собирает объектный модуль, запускает его
в Дубне **и** в dispak (переиспользуется проверенный
`pas2c-metamorph/dispak/runhotest.sh`), сверяет вывод с нативной программой
NanoLang и с ожидаемым значением. Сравнение сводится к верхнему регистру:
эмуляторы печатают через KOI-7 заглавными буквами.

```sh
sh run-e2e.sh examples/arith.nano 42
sh run-e2e.sh examples/arith2.nano '7
42'
sh run-e2e.sh examples/negative.nano -7
sh run-e2e.sh examples/mutual.nano 100
sh run-e2e.sh examples/while_sum.nano 15
sh run-e2e.sh examples/strings.nano 'HELLO FROM NANO2P2C'
```

Все шесть эталонов проходят в обеих средах. Для эталонного примера:

```
native output: 42
BESM-6 output: 42
PASS (DUBNA): nanolang and BESM-6 agree: 42
PASS (dispak): nanolang and BESM-6 agree: 42
```

| Пример | Проверяемое свойство | Ожидаемый вывод |
| --- | --- | --- |
| `arith.nano` | сложение, вызов функции | `42` |
| `arith2.nano` | вычитание, умножение, два `println` | `7`, `42` |
| `negative.nano` | отрицательный результат | `-7` |
| `mutual.nano` | взаимная рекурсия через `if/else` | `100` |
| `while_sum.nano` | локальные инициализаторы, цикл `while` | `15` |
| `strings.nano` | строковый литерал в `printf` | `HELLO FROM NANO2P2C` |

Пути по умолчанию можно переопределить переменными `NANOLANG`, `PAS2C`,
`NANOC`, `DUBNA`. Рабочий каталог создаётся через `mktemp -d` и не удаляется,
чтобы сохранить proof-артефакты (`program.c`, `program.p2c`, `program.o`,
`run.lst`).

## Роль в учебной среде

- этап 2 (разработка): альтернативный frontend для задач на NanoLang;
- этап 3 (расширение): объектный модуль Дубны, совместимый с PERSO;
- этап 6 (испытания): сверка вывода нативной и БЭСМ-6 программ.
